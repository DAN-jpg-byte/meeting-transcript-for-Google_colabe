前提: [experiment_話者分離_結果.md](experiment_話者分離_結果.md)（22分の音声での結果）／ 引き継ぎ: [handoff_6.md](handoff_6.md)

## 目的

22分の音声では、話者分離は約1分・GPU メモリ 1.6GB で、話者の正確さは 98.6% だった。本番は 2.5〜4時間なので、次の3つを確かめる。

1. **メモリ**: 長くなっても、Colab（T4 GPU・RAM）に収まるか
2. **時間**: 現実的な時間で終わるか（見込み: 4時間で話者分離 約10分、クリップごとの文字起こし 約25分）
3. **安定性**: 最初から最後まで、SPEAKER_00 / 01 が同じ人を指し続けるか（途中で入れ替わらないか）

この結果で、本体に取り込むときの設計が変わる（一番下の「判断」）。

## Step 0: 音声の用意（ユーザー）

- [x] 2.5〜4時間の音声を、Drive に置く（2026-10-09 ユーザーが `01_input` に置いた。MP3 約214MB の1本のみ）。置き場所は `01_input` でよい（Step 1 の設定でファイル名を指定するので、他の音声と並んでも大丈夫）
- 長い音声がない場合の代案: 今の22分の音声を ffmpeg で8本つなげて、約3時間の音声を作る。**メモリと時間は確かめられるが、安定性（話者が入れ替わらないか）は確かめられない**（同じ会話の繰り返しなので）

## Step 1: ノートブックの準備（エージェント）

変更ファイル: `experiment_diarization.ipynb`（セルを直接編集する。生成スクリプトは無い）

- [x] **`SOURCE_FILE_NAME` を追加**（Step 1-2 の設定セル）。`None` なら今まで通り先頭の1本。指定があれば、そのファイルを使う
- [x] **`EXPERIMENT_SUBDIR` を追加**: 音声ごとに別フォルダ（`04_temp/experiment_diarization/{名前}/`）に保存する。**これをしないと、`whisper_aligned.json` や `clip_texts.json` が22分の音声の結果と混ざり、別の音声の保存を読んでしまう**（`clip_texts.json` のキーは時刻だけなので、衝突する）。既存の結果は、フォルダ直下に残っているので、そのまま動くようにする（`EXPERIMENT_SUBDIR` が空なら今まで通り）
- [x] **`MAX_MINUTES` を追加**: `None` なら全部、数字ならその長さだけ（ffmpeg の `-t`）。60分 → 全体、と段階的に試すため
- [x] **Step 5 を単独で動かせるようにする**: 今は Step 5-3（exp-22）が、Step 4-2（exp-16）で作る `show_dialogue` / `save_dialogue` / `exclusive_of` を使う。長い音声では Step 3（条件 B）と Step 4（全体の文字起こし）は不要なので、この3つの関数を Step 2-1（exp-8）に移して、Step 3・4 を飛ばせるようにする。各セルの「前のセルを飛ばしていないか」の確認（`GUARDS`）も見直す
- [x] **長時間用の表示**: 話者分離・文字起こしの前後で、Colab の RAM とGPU メモリの使用量を表示する。進み具合（何件中何件）は、すでに25件ごとに表示している
- [x] 手元（偽データ）で確認 → コミット・push（2026-10-09）

注意（長い音声で効く所）:
- `load_waveform` は wav 全体をメモリに読み込む。4時間 = 約1GB（float32）。T4 の RAM では収まる見込みだが、表示で確かめる
- `clip_texts.json` は25件ごとに保存されるので、Colab が切れても続きから再開できる（`cached()` の考え方と同じ）
- インストールのセルのあと、ランタイムが再起動する。再起動のあとは Step 1-2 から順に実行する

## 判断

| 結果 | 採用するときの設計 |
|---|---|
| **全体を一括で、メモリ・時間とも問題なし。最後まで話者が安定** | 話者分離は**一括で処理**。設計が単純（チャンク分割は不要） |
| 全体は動くが、**途中で SPEAKER が入れ替わる** | 相談メモの案（30分程度のチャンク＋1分のりしろで、話者 ID をつなぐ）が必要。作る部分が増える |
| **メモリ不足で落ちる** | チャンク分割が必須（同上）。または、より大きいGPU（L4 など）を使う |
| 60分は動くが全体で時間がかかりすぎる | チャンク分割で並べる・途中保存を細かくする、を検討 |
