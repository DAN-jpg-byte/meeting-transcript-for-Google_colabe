## Step 3: 条件 B（人数を指定）と比較

- [x] セル（exp-12）: `num_speakers=2` で実行 → `diarization_B.json`
- [x] 比較（`compare_results`）: 0.1秒ごとに「誰が話しているか」に直して A と B を比べる
  - SPEAKER 番号が入れ替わっていても、一致が多くなる対応を自動で選ぶ
  - 一致の割合、食い違いの時間、片方だけが検出した時間、**食い違いが長い場所の上位10**（聞き比べの目印）を表示
- 手元で確認済み: 偽の結果で、入れ替わりの補正・食い違いの検出・人数が違う場合の案内
- **Colab で確認済み（2026-10-07）**:
  - B も 2人検出。処理時間 61.3秒（A は 61.8秒）
  - **A と B は 100% 一致**（両方が話者を検出した 1085秒すべてで同じ、食い違い 0秒）
  - 理由: A がもともと正しい人数（2人）を当てていたので、2人指定しても結果が変わらなかった
  - 結論: **この音声では人数を教えなくてよい**。ただし「人数が合っている」は「誰が話したかが合っている」ことの保証ではない（Step 5 で耳で確認）
  - 人数のヒントが効くのは、A が人数を間違えたときだけ。今回の音声では試せていない

**完了の目安**: A と B の違いが1画面で見える。→ 達成

## Step 4: 文字起こしと突き合わせ

- [x] セル（exp-14）: WhisperX で文字起こし（本体と同じ `large-v3`・日本語・batch_size=4）＋文字ごとの時間（アライメント）→ `whisper_aligned.json`
  - 保存済みなら読み込むだけ（やり直さない）。文字数のチェック（毎分20文字未満なら警告）つき
  - 依存関係: whisperx 3.8.6 は `pyannote-audio>=4.0.0` を要求するので、pyannote 4.x と同じ環境に入る見込み。インストールのセルに `whisperx` と `numba>=0.61` を足した（**Colab で確認が必要**）
- [x] セル（exp-16）: 文字ごとに、時間が一番重なる話者を割り当てて、同じ話者が続く部分を1つの発言にまとめる（Python だけの処理）
  - 同時発話を除いた版（`exclusive_segments`）を使う
  - 時間が取れなかった文字は直前の話者に、どの区間とも重ならない文字は一番近い区間の話者にする
- [x] 出力: `[時刻] SPEAKER_xx：発言` 形式のテキスト → `result_A.txt`
  - A と B が同じなら B は作らない（今回は同じ）。違うときだけ `result_B.txt` も作る
- 手元で確認済み: 偽の文字起こしと話者区間で、割り当て・まとめ・時間なしの文字・保存・B が違う場合
- **Colab で確認済み（2026-10-07）**:
  - `whisperx` を `pyannote.audio` と同じインストールで入れても、衝突せず動いた
  - 文字起こし＋アライメントは約2分（22分の音声）。話者分離は条件 A 58秒・B 56秒、GPU メモリ最大 1.6GB
  - 結果: 発言 **205**、うち **5文字以下の短い発言 68（33%）**。文字数は SPEAKER_00 が 1996、SPEAKER_01 が 3058（合計約5050文字 = 毎分約230文字）
  - 内容は銀行の電話での案内（男性2人）。**大きな役割分担は合っているように読める**（SPEAKER_01 が長く説明する側、SPEAKER_00 が質問・返事をする側）
  - **気になる点（読んだ所見。耳での確認は Step 5）**:
    1. 文末の1〜2文字が、次に話す人に付いてしまう（例:「…でいらっしゃいます｜か?」「…ございま｜す」「…ですけ｜れど」）。相手の相づちが重なる所で起きている
    2. 1文字だけの断片（「は」「す」「し」「て」「な」）が、別の人の発言として何度も出る。短い発言 68件の多くがこれと思われる
    3. 一部、別の人の発言がまとまって混ざる所がある（0:00:13 付近、0:00:33 付近）。話者分離の境界か、文字ごとの時間のずれかは未確認
  - 「はい」などの相づちが、そもそも文字起こしに出ていない可能性がある（毎分約230文字は、本体の目安 300〜400 より少なめ）

**完了の目安**: 会話の形のテキストができる。→ 達成
