# 要件定義：話者分離（pyannote Community-1）の実験

作成日: 2026-10-07
ブランチ: `experiment/diarization`
戻り先: タグ `v2.1.0`（Gemini で話者特定する方式の最終版）
元の相談メモ: [長時間音声の文字起こし＋話者分離システム設計.md](長時間音声の文字起こし＋話者分離システム設計.md)

---

## 目的

pyannote Community-1 で話者分離をやり直したら、**実用になる精度が出るか**を、短い実音声で確かめる。
本体（`notebook.ipynb`）を作り替えるかどうかは、この結果を見て決める。

## 背景

- v2.0 で WhisperX の話者分離を廃止した。理由は「精度が低かった」（具体的な記録なし）。
- 当時は Community-1 を、人数のヒントなし・音声全体を1回で処理していた（OLDnotebook のログで確認）。
- 相談メモは、同じ Community-1 に「チャンク分割・のりしろ・人が名前を対応づける」を足す案。
- 精度の低さの原因が分からないまま大きく作ると、同じ失敗をするおそれがある。だから先に小さく試す。

## 実験でやること

使う音声: `MyDrive/MeetingTranscript/01_input/新規録音 14.m4a`（約11MB）

| 条件 | 内容 |
|---|---|
| A | 人数のヒントなし（前回と同じ条件） |
| B | 人数を指定する（`num_speakers=2`） |

各条件で次を出す。

1. 話者ごとの区間（開始秒・終了秒・SPEAKER_xx）を一覧表示
2. 検出された人数、話者ごとの合計発話時間
3. WhisperX の文字起こしと時間で突き合わせた「SPEAKER_xx：発言」形式のテキスト
4. 結果を Drive に保存（`04_temp/experiment_diarization/` に条件別）

※ 実験の進行で、**話者で先に区切ってから文字起こしする Step 5 まで拡張した**。経過は [roadmap_話者分離実験.md](roadmap_話者分離実験.md)、結果は [experiment_話者分離_結果.md](experiment_話者分離_結果.md)

## 合否の見方（人が確認する）

正解の記録はない。**実験者（ユーザー）が音声を聞いて確認する。**

- 検出された人数が実際と合っているか
- 話者が入れ替わる場所が、実際の交代とおおむね合っているか
- 短い相づち（「はい」「そうですね」）で話者がぶれないか
- 条件 A と B で、見た目の差がどれくらいあるか

## 作らないもの（今回の範囲外）

- 30分チャンク分割・のりしろ・話者IDの対応づけ（実験で「単体の精度は使える」と分かってから）
- 人が SPEAKER 番号に名前を対応づける仕組み
- Gemini 側の変更、Notion 出力の変更
- `notebook.ipynb` の変更

## 守ること

- **本体の `notebook.ipynb` は変えない。** 実験専用の `experiment_diarization.ipynb` を作る。
- **入力音声を動かさない・消さない。** 本体は成功すると `01_input` から音声を移動するが、実験ではコピーだけ使う。
- `HF_TOKEN` は Colab のシークレットから読む。コードに直接書かない。
- Hugging Face で Community-1 の利用条件に同意済みである必要がある（未同意ならノートブックの冒頭で案内して止まる）。
- コメントは日本語、変数名・関数名は英語。

## 使う技術

| 技術 | 用途 |
|---|---|
| pyannote.audio 4.x（Community-1） | 話者分離 |
| WhisperX | 文字起こしと単語の時間 |
| ffmpeg | 音声を 16kHz・モノラルに変換 |
| Google Colab（GPU） | 実行場所 |
