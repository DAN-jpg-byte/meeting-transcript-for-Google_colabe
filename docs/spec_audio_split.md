# 要件定義：長時間音声の無音分割機能

作成日: 2026-08-21

---

## 背景・目的

- 300分（5時間）クラスの長時間ミーティング音声を WhisperX にそのまま渡すと、GPUメモリ不足でランタイムがクラッシュする（[handoff_4.md](handoff_4.md) 参照。`batch_size` 16→4 の対策だけでは長時間音声への根本対策にならない）
- **音声をあらかじめ10分前後の塊に分割してから、チャンクごとに WhisperX へ渡す**ことで、1回あたりの処理負荷を抑え、クラッシュを回避する
- 単純に時間で機械的に切ると、発言の途中でブツッと切れて文字起こし精度が落ちるため、**無音（相対的に静かな区間）を見つけてそこを境目にする**

---

## 処理フロー（Step3の変更）

```
【音声ファイル（例：300分）】
    ↓
【Step 3-a: 無音検出による分割】  ※新規
    - pydub で音声を読み込み、無音区間を検出
    - 目標時刻（10分・20分・30分…）に近い無音区間を境目としてチャンクに分割
    - 分割した音声チャンクを /content/ 配下に一時保存

    ↓
【Step 3-b: チャンクごとに WhisperX 文字起こし】  ※既存Step3を拡張
    - WhisperX モデルは1回だけロードし、チャンクごとにループしてtranscribe
    - 各チャンクの文字起こしテキストを順番に連結
    - チャンク音声ファイルは使い終わったら削除

    ↓
【Step 4以降】
    - 変更なし（テキストだけを扱うため、分割していたことを意識しない）
```

## 無音検出・分割アルゴリズム

1. `pydub.silence.detect_silence()` で音声全体から「無音とみなせる区間」を全部リストアップする
   - 判定基準（初期値・調整可能）
     - `silence_thresh`: 音声全体の平均音量 − 16dB（pydubのデフォルト相当）
     - `min_silence_len`: 700ms（これより短い無音は無視。息継ぎなどでの誤分割を防ぐ）
2. 目標カット時刻（10分, 20分, 30分, …）ごとに、その近くにある無音区間を探す
   - 探索範囲は**目標時刻 ± 60秒**から開始し、見つからなければ ±120秒 → ±240秒 …と段階的に広げる（採用済み方針）
   - 見つかった無音区間の**中央の時刻**をカットポイントにする
3. 全てのカットポイントで音声を切り出し、チャンクごとの音声ファイル（wav）を `/content/chunks/` に一時保存する
   - 60分の音声なら6個前後、300分なら30個前後のチャンクになる想定
4. 全チャンクの文字起こしが終わったら `/content/chunks/` ごと削除する（Google Driveには残さない・採用済み方針）
