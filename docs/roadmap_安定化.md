# roadmap: 長時間音声の安定化（ローカル版を参考に）

作成日: 2026-10-07
ステータス: 承認済み（2026-10-07）。要件は [spec_安定化.md](spec_安定化.md)

## 目的

長時間音声（3時間超）の処理中に Colab が切れたり Gemini が失敗したりしても、
**終わった分をやり直さずに続きから再開できる**ようにする。

## 参考にするローカル版の考え方

- `batch_runner.py` の `_cached_step`：段階ごとの結果をファイルに保存し、再実行時は保存済みの段階を飛ばす
- `audio_chunker.py` の `MIN_TAIL_SEC`：最後の短すぎる切れ端を前のチャンクに合流させる
- `title_generator.py`：内容から議事録タイトルを作る

## 決定事項

- 途中保存の置き場所は **Google Drive の `04_temp/`**（案A）。Colab が切れても残る
- コードの整理（`.py` への分割・テスト）は、安定化が終わってから改めて決める（このロードマップの対象外）
- Gemini は **成功した呼び出しのあとに毎回5秒待つ**（RPM 15 は最低4秒間隔なので、余裕を見て5秒）。失敗時は別途リトライする（Step 2 参照）

- Gemini のリトライは最大3回、待ち時間は 10秒 → 30秒 → 60秒（承認済み）
- 長時間音声の再テストは、この修正を入れたあとに行う（Step 5）

## ステップ

### Step 1: 途中保存の土台と、WhisperX のチャンク単位保存

- [ ] 変更ファイル: `notebook.ipynb`（Step 2 の設定セル、Step 3 の各セル）
- 実装イメージ:
  - Step 2 に `TEMP_DIR = f'{BASE_DIR}/04_temp'` を追加
  - 保存先の名前は `04_temp/{ファイル名}_{ファイルサイズ}/` にする
  - 対象ファイルは `audio_files` をファイル名順に並べ替えてから先頭を選ぶ（再開時に別のファイルを選ばないため）
  - 共通ヘルパー `cached(path, compute_fn)` を作る（あれば読む、なければ計算して保存）
  - WhisperX はチャンクごとに `whisper_000.txt` として保存。再実行時は保存済みチャンクの文字起こしを飛ばす
- ポイント:
  - 同名で中身が違うファイルの古い保存を読んでしまわないよう、ファイルサイズを保存先名に含める
  - 現状は `raw_transcript.txt` を保存するだけで読み戻していない。ここを「読み戻す」形に変える
  - 音声分割自体は毎回やり直す（結果は同じになるので、再開に影響しない）

### Step 2: Gemini のリトライと、チャンク単位保存

- [ ] 変更ファイル: `notebook.ipynb`（Step 4a・4b のセル）
- 実装イメージ:
  - ヘルパー `call_gemini(prompt)` を作り、失敗したらリトライする
  - 暫定値: 最大3回、待ち時間は 10秒 → 30秒 → 60秒
  - 成功した呼び出しのあとに毎回5秒待つ（RPM 15 対策。待ち時間は設定値 `GEMINI_WAIT_SEC = 5` として Step 2 の設定欄に置く）
  - 4a・4b ともにチャンクごとに `4a_000.txt` / `4b_000.txt` として保存し、再開時に飛ばす
- ポイント:
  - `response.text` が取れない場合（安全フィルタ等）も、エラー内容を表示してリトライ対象にする
  - リトライを使い切って失敗したら、保存済みの分を残したまま止める（次回再実行で続きから）

### Step 3: 最後の短い切れ端を前のチャンクに合流

- [ ] 変更ファイル: `notebook.ipynb`（音声分割のセル）
- 実装イメージ: 最後のチャンクが2分未満なら、その手前のカットポイントを取り除く
- ポイント: ローカル版の `MIN_TAIL_SEC = 120` と同じ値にする

### Step 4: 成功後の後片付け

- [ ] 変更ファイル: `notebook.ipynb`（Step 6 のセル）
- 実装イメージ: Notion 投稿と議事録保存が終わったら、そのファイルの `04_temp/` の保存分を削除する
- ポイント:
  - 失敗したときは保存を残す（再開のため）
  - 参加者の入れ替えをしたときに古い保存を読まないよう、README に「やり直したいときは `04_temp/` を空にする」と明記する

### Step 5: 動作確認と記録

- [ ] 短い音声で通しテスト（保存と削除の動きを確認）
- [ ] 長時間音声で、途中でわざとランタイムを切ってから再実行し、続きから再開できるか確認
- [ ] README と `docs/handoff_5.md` を更新（notebook の最終更新日時も記入）
