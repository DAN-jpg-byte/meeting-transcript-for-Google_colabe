# 要件定義：長時間音声処理の途中保存・再開とGeminiリトライ

作成日: 2026-10-07

---

## 背景・目的

- 3時間超の長時間ミーティングでは、処理が数時間かかる。その間に Colab の切断や Gemini の一時エラー・RPM 制限が起きると、**現状は最初からやり直しになる**
  - Step 3 は生テキストを保存するが、再実行時に読み戻していない
  - Step 4a / 4b の結果は保存していない
  - Gemini 呼び出しにはリトライも待ち時間もない
- 参考：ローカル版（`C:\dev\python\meeting-transcript-local`）の `batch_runner.py`。段階ごとの結果をファイルに保存し、再実行時は保存済みの段階を飛ばす
- **目的：処理が途中で止まっても、終わった分をやり直さずに、再実行で続きから再開できるようにする**

---

## やること（要件）

### 1. 途中保存と再開

- 保存先：Google Drive の `MeetingTranscript/04_temp/{ファイル名}_{ファイルサイズ}/`
  - ファイルサイズを含めるのは、同名で中身の違う音声を入れたときに古い保存を読まないため
- 保存する単位（チャンクごと）

  | 段階 | 保存ファイル名 | 中身 |
  |---|---|---|
  | Step 3（WhisperX） | `whisper_000.txt` 〜 | そのチャンクの文字起こし |
  | Step 4a（誤字補正） | `4a_000.txt` 〜 | そのチャンクの補正結果 |
  | Step 4b（話者分離） | `4b_000.txt` 〜 | そのチャンクの話者分離結果 |

- 再実行したとき、保存済みのチャンクは計算せずに読み込んで次へ進む
- 保存は1チャンク終わるたびに行う（段階が全部終わるのを待たない）

### 2. Gemini のリトライと待ち時間

- 成功した呼び出しのあとに毎回 **5秒** 待つ（設定値 `GEMINI_WAIT_SEC = 5`。RPM 15 は最低4秒間隔のため、余裕を見て5秒）
- 失敗したら最大 **3回** リトライする。待ち時間は **10秒 → 30秒 → 60秒**
- 失敗の対象：通信エラー、レート制限、`response.text` が取れない場合（安全フィルタ等）
- 3回とも失敗したら、エラー内容を表示して処理を止める。保存済みの分は残す（再実行で続きから再開できる）

### 3. 音声の分割を ffmpeg に変え、最後の短い切れ端も合流させる

**なぜ変えるか**：今の pydub は音声を丸ごとメモリに読み込む。5時間（300分）級だと3GB超になり、Colab（約12GB）では余裕が小さい。ffmpeg は少しずつ読むのでメモリをほとんど使わず、速い。参考：ローカル版 `audio_chunker.py`

- **Drive の音声を、最初に Colab 側の一時領域（`/content/work/`）にコピーする**
  - Drive はネット越しなので、ffmpeg が何度も読むと遅くなるため
  - コピーは Step 3 の最初に行い、Step 6 で削除する
- 分割の手順（ffmpeg / ffprobe を使う）
  1. 音声の長さを取る（ffprobe）
  2. 全体の平均音量を取る（volumedetect）
  3. 平均音量 − 16dB より静かな区間を探す（silencedetect。0.7秒以上の無音だけ）
  4. 目標時刻（10分ごと）の近くにある無音の中央で切る。探す範囲は ±60秒 → ±120秒 → ±240秒 → ±480秒と広げる（今の値のまま）
  5. 見つからなければ、目標時刻で機械的に切る
- 切り出したチャンクは **16kHz・モノラルの wav** で保存する（Whisper は内部で16kHzモノラルに変換するので、精度は変わらない。ファイルも小さい）
- 動画ファイル（mp4 等）は、音声だけを取り出して切る
- 音声が10分以下なら、分割せず1チャンクとして扱う
- **最後のチャンクが2分（120秒）未満なら**、手前のカットポイントを取り除き、前のチャンクに含める（ローカル版の `MIN_TAIL_SEC = 120` と同じ）
- **カットポイントを `04_temp/{ファイル名}_{サイズ}/cut_points.json` に保存する**
  - 再実行のとき、同じ位置で切ることを保証する（`whisper_000.txt` などの番号が、毎回同じ時間帯を指す必要があるため）
  - あれば読む、なければ検出して保存する
- ffmpeg が使えない場合は、Step 2 で分かりやすいエラーを出して止める（Fail Fast）
- pydub は不要になるので、Step 1 のインストールから外す

### 4. 文字起こしが短すぎたらエラーにする

- 参考：ローカル版 `transcriber.py` の `_verify_length`（`MIN_CHARS_PER_MINUTE = 20`）
- Step 3 で全チャンクの文字起こしが終わったあと、**Gemini に進む前に**チェックする
  - 最低文字数 ＝ 音声の長さ（分）× 20文字
  - 文字起こしの総文字数がそれ未満なら、エラーにして止める
- 20文字/分は、日本語の会話（毎分300〜400文字）よりずっと低い下限。ほぼ無言の録音を誤って弾かないための余裕
- エラーのとき：
  - メッセージに、総文字数・音声の長さ・最低必要な文字数を表示する
  - そのファイルの Step 3 の保存（`whisper_*.txt`）を**削除してから**止める（残すと、再実行しても同じ空の結果を読んで同じエラーになるため）
- あわせて、チャンクごとの文字数を表示する（どのチャンクが空かを見つけやすくするため）

### 5. 成功後の後片付け

- Notion 投稿と議事録保存が終わったら、そのファイルの `04_temp/{ファイル名}_{ファイルサイズ}/` を削除する
- 途中で失敗したときは削除しない（再開のため）

### 6. 対象ファイルの選び方を安定させる

- 現状は `audio_files[0]` を処理する。ファイルの並びが毎回同じとは限らず、再開のときに別のファイルを選ぶと保存が使われない
- `audio_files` をファイル名順に並べ替えてから先頭を選ぶ

## 処理フロー（変更後）

```
【Step 2: 認証・設定】
    - TEMP_DIR・GEMINI_WAIT_SEC などの設定を追加
    - ffmpeg / ffprobe が使えるか確認（なければここで止まる）
    - 対象ファイルを決める（ファイル名順の先頭）
    - 保存先フォルダ 04_temp/{ファイル名}_{サイズ}/ を決める

【Step 3: 音声分割 → WhisperX】
    - 音声を Colab 側にコピー → ffmpeg で分割（最後が2分未満なら前に合流）
    - カットポイントは cut_points.json に保存（再実行でも同じ位置で切る）
    - チャンクごとに: 保存があれば読む／なければ文字起こしして保存
    - 全チャンク終了後、文字数が短すぎないかチェック（短すぎたら Step 3 の保存を消して止まる）

【Step 4a / 4b: Gemini】
    - チャンクごとに: 保存があれば読む／なければ Gemini を呼んで保存
    - Gemini 呼び出し: 失敗したらリトライ、成功したら5秒待つ

【Step 5: Notion 出力】 変更なし

【Step 6: 後片付け】
    - 04_temp の保存分を削除する（追加）
```

## 完成の基準

- 短い音声：これまでどおり最後まで動き、終わったら `04_temp/` の保存が残らない
- 長時間音声：途中でランタイムを切って再実行しても、保存済みのチャンクを飛ばして続きから進む
- Gemini が一時的に失敗しても、リトライで復帰する（3回失敗したときは、保存を残して止まる）
- 5時間級の音声でも、分割中にメモリが急に増えない（Colab の RAM 表示で確認）。分割結果が前と変わらない
- 文字起こしがほぼ空のとき、Gemini と Notion に進まずにエラーで止まる（そのあと再実行すれば、文字起こしからやり直せる）
