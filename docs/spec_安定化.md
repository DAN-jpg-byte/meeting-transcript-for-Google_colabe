# 要件定義：長時間音声処理の途中保存・再開とGeminiリトライ

作成日: 2026-10-07

---

## 背景・目的

- 3時間超の長時間ミーティングでは、処理が数時間かかる。その間に Colab の切断や Gemini の一時エラー・RPM 制限が起きると、**現状は最初からやり直しになる**
  - Step 3 は生テキストを保存するが、再実行時に読み戻していない
  - Step 4a / 4b の結果は保存していない
  - Gemini 呼び出しにはリトライも待ち時間もない
- 参考：ローカル版（`C:\dev\python\meeting-transcript-local`）の `batch_runner.py`。段階ごとの結果をファイルに保存し、再実行時は保存済みの段階を飛ばす
- **目的：処理が途中で止まっても、終わった分をやり直さずに、再実行で続きから再開できるようにする**

---

## やること（要件）

### 1. 途中保存と再開

- 保存先：Google Drive の `MeetingTranscript/04_temp/{ファイル名}_{ファイルサイズ}/`
  - ファイルサイズを含めるのは、同名で中身の違う音声を入れたときに古い保存を読まないため
- 保存する単位（チャンクごと）

  | 段階 | 保存ファイル名 | 中身 |
  |---|---|---|
  | Step 3（WhisperX） | `whisper_000.txt` 〜 | そのチャンクの文字起こし |
  | Step 4a（誤字補正） | `4a_000.txt` 〜 | そのチャンクの補正結果 |
  | Step 4b（話者分離） | `4b_000.txt` 〜 | そのチャンクの話者分離結果 |

- 再実行したとき、保存済みのチャンクは計算せずに読み込んで次へ進む
- 保存は1チャンク終わるたびに行う（段階が全部終わるのを待たない）

### 2. Gemini のリトライと待ち時間

- 成功した呼び出しのあとに毎回 **5秒** 待つ（設定値 `GEMINI_WAIT_SEC = 5`。RPM 15 は最低4秒間隔のため、余裕を見て5秒）
- 失敗したら最大 **3回** リトライする。待ち時間は **10秒 → 30秒 → 60秒**
- 失敗の対象：通信エラー、レート制限、`response.text` が取れない場合（安全フィルタ等）
- 3回とも失敗したら、エラー内容を表示して処理を止める。保存済みの分は残す（再実行で続きから再開できる）

### 3. 最後の短い切れ端の合流

- 音声分割の最後のチャンクが **2分（120秒）未満** なら、手前のカットポイントを取り除き、前のチャンクに含める
- 値はローカル版の `MIN_TAIL_SEC = 120` と同じ

### 4. 成功後の後片付け

- Notion 投稿と議事録保存が終わったら、そのファイルの `04_temp/{ファイル名}_{ファイルサイズ}/` を削除する
- 途中で失敗したときは削除しない（再開のため）

### 5. 対象ファイルの選び方を安定させる

- 現状は `audio_files[0]` を処理する。ファイルの並びが毎回同じとは限らず、再開のときに別のファイルを選ぶと保存が使われない
- `audio_files` をファイル名順に並べ替えてから先頭を選ぶ

## 処理フロー（変更後）

```
【Step 2: 認証・設定】
    - TEMP_DIR・GEMINI_WAIT_SEC などの設定を追加
    - 対象ファイルを決める（ファイル名順の先頭）
    - 保存先フォルダ 04_temp/{ファイル名}_{サイズ}/ を決める

【Step 3: 音声分割 → WhisperX】
    - 音声を分割（最後が2分未満なら前に合流）
    - チャンクごとに: 保存があれば読む／なければ文字起こしして保存

【Step 4a / 4b: Gemini】
    - チャンクごとに: 保存があれば読む／なければ Gemini を呼んで保存
    - Gemini 呼び出し: 失敗したらリトライ、成功したら5秒待つ

【Step 5: Notion 出力】 変更なし

【Step 6: 後片付け】
    - 04_temp の保存分を削除する（追加）
```

## 運用上の注意（README に記載する）

- 参加者を入れ替えて **最初からやり直したいとき**は、`04_temp/` の中のそのファイルのフォルダを削除する（保存済みの 4b を読んでしまうため）
- 保存はファイル名とサイズで判定する。同じ音声を別名にしても、別の音声として扱われる

## 完成の基準

- 短い音声：これまでどおり最後まで動き、終わったら `04_temp/` の保存が残らない
- 長時間音声：途中でランタイムを切って再実行しても、保存済みのチャンクを飛ばして続きから進む
- Gemini が一時的に失敗しても、リトライで復帰する（3回失敗したときは、保存を残して止まる）
