# 【仕様書】長時間会議の自動文字起こし・議事録作成システム

作成日: 2026-04-18

---

## 1. 目的

税理士等との長時間（3〜4時間）のミーティング音声を、コストを抑えつつ高精度に文字起こしし、参加者プロフィールに基づいた対話形式の議事録としてNotionへ集約する。

---

## 2. 技術スタック

| 役割 | ツール | 理由 |
|------|--------|------|
| 実行環境 | Google Colab（無料版） | GPUを無料で利用し、長時間音声を高速処理 |
| 文字起こし | WhisperX | 高精度な文字起こし＋話者分離（誰が話したか）を実現 |
| 話者分離認証 | Hugging Face Token | Pyannoteモデルの使用に必須（無料） |
| 参加者データ | Googleスプレッドシート | 参加者の名前・役割・プロフィールを管理 |
| 文章整形 | Gemini API（1.5 Flash/Pro） | 長文対応・話者特定・専門用語補正 |
| 最終出力 | Notion API | 議事録のストック・検索・共有 |

---

## 3. ディレクトリ構成（Google Drive）

```
API_Whisper_System/
├── 01_Input_Audio        # 処理前の音声ファイル（mp3, m4a等）を投入
├── 02_Processed_Audio    # 完了した音声の移動先
├── 03_Text_Output        # 生成されたテキスト/Markdownの保存先
└── 文字起こし管理シート     # スプレッドシート（参加者名簿・処理ログ）
```

---

## 4. スプレッドシートのレイアウト

### シート名：本日の参加者

| 列 | 内容 | 例 |
|----|------|----|
| 名前 | 実名 | 田中 太郎 |
| 役割 | その日の立場 | 税理士 / 説明担当 / 依頼者 |
| プロフィール | Geminiに渡すメモ | 「主に説明する側。専門用語多め」 |

**運用ルール：**
- 毎回のミーティング前にこのシートを書き換える
- 参加者は通常2〜3名

---

## 5. 処理フロー

1. **音声投入:** `01_Input_Audio` に録音ファイル（1本）をアップロード
2. **Colab実行:** ノートブックを開き「すべてのセルを実行」
3. **文字起こし（WhisperX）:** GPUで文字起こし＋`SPEAKER_00`等のラベルを付与
4. **参加者情報取得:** スプレッドシートから「本日の参加者」を読み込み
5. **整形（Gemini）:**
   - テキストを **1万文字単位** に分割して送信（精度維持のため）
   - `SPEAKER_XX` を実名に置換
   - 専門用語の補正を実行
   - 分割結果を結合して全文を生成
6. **Notion出力:** 議事録ページをAPI経由で作成
7. **整理:** 処理済み音声を `02_Processed_Audio` へ自動移動

---

## 6. Notionページのフォーマット

### ページタイトル
`議事録_YYYY-MM-DD`

### プロパティ
| プロパティ | 内容 | 例 |
|-----------|------|----|
| 日付 | ミーティング日 | 2026-04-18 |
| 参加者 | 名前と役割 | 田中（税理士）、山田（依頼者） |

### 本文（対話形式・全文）
```
田中: 今回の決算についてですが〜〜〜
山田: それはつまりどういうことですか？
田中: 簡単に言うと〜〜〜
...
```

## 7. 事前準備チェックリスト

- [ ] **Google Drive:** ディレクトリ構成の作成
- [ ] **Hugging Face:** アカウント作成・3つのモデルへの同意・Readトークンの発行
- [ ] **Google AI Studio:** Gemini APIキーの発行
- [ ] **スプレッドシート:** 参加者名簿シートの作成（列: 名前・役割・プロフィール）
- [ ] **Notion:** インテグレーション作成・データベースIDの取得
- [ ] **Colab:** 必要ライブラリのインストール確認

---

## 8. 制約・前提条件

- 実行環境はGoogle Colab無料版（最大12時間/セッション）
- 音声ファイルは1セッション1本
- 参加者は通常2〜3名（話者分離の精度に影響しないため問題なし）
- Geminiへの送信は1万文字単位に分割（出力精度を維持するため）
